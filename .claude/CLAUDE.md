# Working in this repo

This is the live `~/.claude` config: an edit to a skill takes effect in running Claude Code sessions immediately. That immediacy is why the live directory is versioned in place rather than a clean repo being synced in, and its price is a working tree holding runtime state, secrets, and foreign checkouts. The allowlist `.gitignore`, the `git ls-files` file lists, and the hand-named test suites all descend from that one decision — weaken none of them without revisiting it.

This file loads only in sessions started inside this repo. The root `CLAUDE.md` is global user memory, loaded into every session in every project, so nothing about this repo goes there or is imported from there. Keep this a `CLAUDE.md`, where `standards/repo-setup.md` asks for an `AGENTS.md`: Claude Code falls back to `AGENTS.md` only in a project with no `CLAUDE.md` of its own, and this one has the global file at its root (tested on 2.1.322: `.claude/AGENTS.md` here did not load).

[`CONTRIBUTING.md`](../CONTRIBUTING.md) holds the tooling, the checks, how each helper is tested, and what a new helper has to be registered with. Read it before changing the `justfile`, `lefthook.yml`, CI or the devcontainer, and before adding or changing a helper or a test suite: one contract suite can write into the live `skills/`.

- **What a commit owes is the pre-commit hook (`lefthook.yml`), not `just check`.** A commit of only markdown and skills triggers nothing in it: review the diff and commit. Don't run `just check` for one by hand, since it fails wherever `shfmt` or `scrut` isn't installed and would block a commit it has nothing to say about.
- **Leave the commit references in tests alone:** a test citing one is pinning that regression.
- **Never loosen the catch-all in `.gitignore`:** secrets and runtime state live in this directory, so everything is ignored by default.
- **No ADRs for how this config is built,** this repo's exception to `standards/documentation.md`. A decision's rationale lives in its commit message; one that must constrain future work (especially "we tried/considered X — don't") gets a one-line guardrail here or in the relevant SKILL.md, citing its commit for the full story (b22d4e3). None of this covers `standards/`, which is a repository of its own and keeps its decision records itself.
- **One home per fact:** what a human acts on before a session exists (setup, model choice) → README; what it takes to change this repo → `CONTRIBUTING.md`; why the config is built this way → `docs/design.md`, which the README only summarises; what an agent working on this repo would get wrong → here; what a skill needs wherever it runs → `references/` or the relevant SKILL.md, named by path since nothing loads them; how I do a kind of work in any repo → `standards/`, which no other file here restates — name the standard and add only what is particular.
- **A standard reaches a session only through its line in the root `CLAUDE.md`,** so a new file there needs that line, naming the work it is read before. A standard every session needs is imported with `@standards/<file>` instead, as `commit-messages.md` is, and has no line (5130d17 has the runs that showed a line is not enough there).
- **`standards/` is a submodule** (`github.com/NicoVIII/standards`): an edit is a commit there plus the moved pin here. Read `references/standards-edits.md` before making one. Leave `submodule.recurse` unset: with it every `git switch` here detaches the submodule's HEAD.
- **Skills and references point into the docs by path.** Several skills read named README sections at run time (`author-skill` → Skills + Workflows; `skill-retro` and `pick-model` → the maturity table), and `claude-md-compact` and `references/skill-conventions.md` send their readers to this file. Grep `skills/` and `references/` before moving, renaming, or cutting a section or a rule (af2f8fb).
- **The repo is public** (`github.com/NicoVIII/claude-config`) and meant to be usable by others, though its primary goal is versioning my own setup, so the README addresses third-party users too. First-person voice in skills ("my repos") is fine: it resolves to whoever runs them.
- **`bin/skill-refiner/ProjectSkillsReadme.md` is written for a stranger who found a `.claude/skills/` folder in their own repo.** It explains what is there and what wrote it, and carries no instruction for maintaining skills: what it seeds must stay *usable* without this config, not maintainable without it (9056afe).
