# Skill conventions

Read this before writing or editing a skill in `~/.claude/skills` or in a repo's own `.claude/skills` — the loop treats both alike. `bin/skill-refiner.sh <skill>` resolves the name in the session repo's `.claude/skills` first, then here, and takes a directory path to force either; the `HISTORY.md` it writes sits beside the `SKILL.md` in whichever tree that is, so a project's log and skill edits ship with the project. Conventions for this repo itself — check suite, tests, doc placement — are in [`.claude/CLAUDE.md`](../.claude/CLAUDE.md), which loads by itself only in a session started in `~/.claude`. This file never auto-loads, so read it rather than a remembered copy.

- Write and refine skills with the most capable model available (currently Fable, otherwise Opus), even when the skill's suggested execution model is Sonnet: skill text is written once but steers every future run, and the hard part is anticipating how a smaller executor will misread it. A skill no maturity table lists has no suggested model — write it for Sonnet, since text spelled out for the weaker executor serves the stronger one. Mechanical edits (typos, renames) don't need this. Deliberate exception: `skill-retro`'s suggested *run* model stays Opus — its edits are anchored to observed friction rather than open-ended authoring, and it runs after every skill iteration, so cost weighs heavier there (1468685).
- Before writing an executable helper for a skill — or deciding whether it belongs at the repo root or in one skill's `scripts/` — read [`helpers.md`](helpers.md). That is the one place those rules live.
- `skills/*/SKILL.md` frontmatter must start at byte 0 (nothing above the first `---`, or it silently fails to parse). The `description` field is the model's only trigger signal — keep it rich in trigger phrases, and free of everything else: every description loads in every session in every project, so a clause describing *how* the skill works routes nothing and bills everywhere. Triggers and scope only; mechanism and rationale belong in the body. Past ~50 words (the current median) something that isn't a trigger has crept in.
- Skills below 🟢 Usable (🚧 WIP, 🧪 Experimental) — per the maturity table where their skills live (`README.md` here, `.claude/skills/README.md` in a project, seeded there by the first entry logged), or per `skill-refiner maturity` where no table lists them — end with a feedback footer asking the executing agent to surface friction, or to log the run itself (`log run`) when it met none, copied verbatim from [`skill-footer.md`](skill-footer.md) — the canonical wording, so no skill is another's source. Add it to every new skill; remove it when a skill graduates to Usable — mature skills are daily drivers where the footer is noise, and `/skill-retro` on demand covers them. `/skill-retro` turns the surfaced friction into skill edits; a self-logged `run` counts toward 🟢 Usable and never toward 🛡️ Battle-tested, which only reviewed runs reach. Nothing follows the footer — upstream attributions belong in the README's credits line, since a `SKILL.md` loads into context on every invocation.
- `HISTORY.md` is written by `skill-refiner` alone while it runs. When it cannot (no dotnet), append each `log` entry by hand as one line in exactly the shape the parser accepts, or every reader of that log aborts: `YYYY-MM-DD · <repo> · <N> words · <event>`, where `<repo>` is the session repo's `origin` name less `.git` (its toplevel directory's name without one), `<N>` is `wc -w` of the SKILL.md at that moment, and `<event>` is the command's words with a colon before the clause (`log retro minor '<clause>'` → `retro minor: <clause>`; `created`, `run`, `retro clean` take none). A new log starts with a `# Skill History` line and a blank line. Don't hand-compute `maturity` or `ratio`: say they were skipped, so the next session that can run the tool makes the README edit.
- In a skill whose steps run in sequence, put each instruction where its inputs exist, not in the section that introduces its topic. Both drifts so far were the same move: a step's dependency changed and its paragraph stayed put (ebbfdaf; `skill-retro`'s maturity check rating a log the run had not been written to yet).
- The agent-marker attribution norm lives in `CLAUDE.md` (Interaction), reversing a3cd73c: ad-hoc writes outside any skill proved uncovered (#6). `author-skill` still requires skills that write publicly to state the marker themselves, for executors without this `CLAUDE.md`.
